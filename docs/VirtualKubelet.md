# Virtual Kubelet

The virtual-kubelet binary (`virtual-kubelet`) registers as a Kubernetes
node and delegates pod execution to an external pod-runner via its
[virtual-kubelet](https://github.com/virtual-kubelet/virtual-kubelet) provider interface.

## How It Works

The virtual kubelet acts as a bridge between the Kubernetes API server
and the pod-runner:

1. Registers a virtual node in the cluster with configurable name,
   labels, and a `virtual-kubelet.io/provider=minimal:NoSchedule` taint.
2. Watches for pods scheduled to the virtual node via informers.
3. Forwards pod lifecycle operations (create, update, delete) to the
   pod-runner HTTPS endpoint (mTLS).
4. Syncs pod status from the pod-runner back to the Kubernetes API.
   The sync loop uses a single bulk `/getAllPodStatuses` call per tick
   plus a local phase cache, so K8s `UpdateStatus` calls only fire on
   actual phase transitions.
5. Reports node capacity, conditions, and addresses fetched from the
   pod-runner.
6. Serves the kubelet API (TLS with a self-signed cert) for
   `kubectl logs` support. The port is configurable via `--kubelet-port`
   (default `10250`).

## Configuration

The virtual kubelet uses two configuration files plus a kubeconfig:

### Kubeconfig

Standard Kubernetes kubeconfig for connecting to the API server. Passed
via `--kubeconfig` or `KUBECONFIG`. Typically generated by the
control-plane on startup (`vk-kubeconfig.yaml`).

### vk-prconfig.yaml (pod-runner client config)

Describes how to connect to the pod-runner. Passed via `--prconfig` or
`PRCONFIG`. Regenerated on every start by the pod-runner.

```yaml
url: "https://pod-runner:443"
nodeName: "tdknode"
namespace: "default"
server:
  tls:
    certificate-authority: "/path/to/ca.pem"     # or certificate-authority-data: "<base64>"
    insecure-skip-tls-verify: false
client:
  id: "vk"
  certificate: "/path/to/client.crt"             # or certificate-data: "<base64>"
  certificate-key: "/path/to/client.key"         # or certificate-key-data: "<base64>"
```

| Field        | Description                                                    |
|--------------|----------------------------------------------------------------|
| `url`        | Pod-runner HTTPS endpoint (required)                           |
| `nodeName`   | Node name to register in the cluster (default: `virtual-node`) |
| `namespace`  | Namespace to watch for pods (default: `default`)               |
| `server.tls` | TLS settings for connecting to pod-runner                      |
| `client`     | Client certificate used for mTLS to pod-runner                 |

### vksysconfig.yaml (runtime tunables)

Persistent, user-editable. Auto-created with defaults in the config
directory on first start.

```yaml
syncSec: 1                # Pod status sync interval (seconds)
podControllerWorkers: 100 # Worker count for the virtual-kubelet pod controller
syncMaxWorkers: 50        # Max concurrent K8s UpdateStatus calls per sync tick
clientQps: 500            # K8s client rate limit (QPS)
clientBurst: 1000         # K8s client burst
```

## Pod-Runner HTTP API

The virtual kubelet communicates with the pod-runner via these endpoints:

| Method | Endpoint                              | Purpose                                          |
|--------|---------------------------------------|--------------------------------------------------|
| POST   | `/createPod`                          | Create a new pod                                 |
| PUT    | `/updatePod`                          | Update an existing pod                           |
| DELETE | `/deletePod?namespace=X&name=Y`       | Delete a pod                                     |
| GET    | `/getPod?namespace=X&name=Y`          | Get a single pod                                 |
| GET    | `/getPodStatus?namespace=X&name=Y`    | Get pod status                                   |
| GET    | `/getPods`                            | List all pods                                    |
| GET    | `/getAllPodStatuses`                  | Bulk status dump used by the sync loop           |
| GET    | `/capacity`                           | Node resource capacity                           |
| GET    | `/nodeConditions`                     | Node health conditions                           |
| GET    | `/nodeAddresses`                      | Node network addresses                           |
| GET    | `/getContainerLogs?...`               | Container log stream                             |

## Command-Line Options

| Flag             | Default            | Description                                                        |
|------------------|--------------------|--------------------------------------------------------------------|
| `--kubeconfig`   | (required)         | Path to kubeconfig file (or `KUBECONFIG`)                          |
| `--prconfig`     | (required)         | Path to vk-prconfig YAML (or `PRCONFIG`)                           |
| `--configdir`    | `<workdir>/config` | Config directory (holds `vksysconfig.yaml`)                        |
| `--workdir`      | `.`                | Working directory (`data/virtual-kubelet/` created under this)     |
| `--logdir`       | `<workdir>/log`    | Log directory                                                      |
| `--log-level`    | `info`             | Log level (`trace`, `debug`, `info`, `warn`, `error`)              |
| `--kubelet-port` | `10250`            | Kubelet API server port (serves `kubectl logs`)                    |
| `--logmaxsizemb` | `100`              | Max log file size in MB                                            |
| `--logmaxfiles`  | `3`                | Max rotated log files to keep                                      |

## Provider

The `PodRunnerProvider` implements the virtual-kubelet Provider interface,
delegating all pod operations to the pod-runner over HTTPS with mTLS.

## Node Registration

The virtual node is registered with:

- **Labels**: `type=virtual-kubelet`, `kubernetes.io/role=agent`,
  `kubernetes.io/hostname=<nodeName>`, `beta.kubernetes.io/os=linux`,
  `alpha.service-controller.kubernetes.io/exclude-balancer=true`
- **Taint**: `virtual-kubelet.io/provider=minimal:NoSchedule`
- **Capacity**: fetched from the pod-runner `/capacity` endpoint
- **Lease**: enabled with 40-second duration

## Status Sync Loop

To keep costs flat at high pod counts, the sync loop uses two techniques:

1. **Bulk fetch** — one call per tick to `/getAllPodStatuses` returns
   `{namespace, name, phase, status}` for every pod.
2. **Phase cache** — a local `map[key]phase` tracks the last phase
   successfully pushed to the K8s API. When the reported phase matches
   the cache, the K8s `Get` + `UpdateStatus` calls are skipped.

At steady state this reduces the sync cost to a single pod-runner call
per tick plus zero K8s API calls.

Actual K8s updates are fanned out with up to `syncMaxWorkers` concurrent
goroutines and retried up to 3 times on conflict/error.

## Logging

Rotating log file at `<logdir>/virtual-kubelet.log` using a klog-style
format. Logrus writes to the file; bootstrap messages (node name,
endpoint, kubeconfig) go to stdout.

## PID Management

Writes a PID file at
`<workdir>/data/virtual-kubelet/pids/<pid>.virtual-kubelet` on startup.
Cleaned up on graceful shutdown (SIGINT/SIGTERM).
